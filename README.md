## 1. 我出的題

「不義」最開始是因為我喜歡靈異的氛圍，才想出這個遊戲。真的動手做，是因為課堂作業，加上剛看過一本靈異小說，從裡面借了一些東西。第一位客人是我自己：第一個親自試玩、按標準驗收的人。像我一樣喜歡在極安靜裡被嚇到、願意慢慢找線索的玩家，就是這款遊戲要給的人。為什麼是我：我很在乎隱藏在背景的氛圍感，那種不講明、要自己聽出來、看出來的東西，是我最在意的地方。

## 2. 我怎麼帶 AI 團隊

這一週把 AI 團隊從「一個 AI 全包」改成三位有名字的人才，各守一件事，做的事寫在 `.opencode/skills` 裡：

| 名字 | 負責什麼 | 什麼時候叫他 |
|---|---|---|
| 溫亦青 | 把老闆定的主題寫成灰盒規格：場景、線索清單、反派設定、節奏 | 要開新的一關、或要改某一關的設計時 |
| 江敘 | 照規格做成能玩的單檔 `.html`，自己實測再交 | 規格定案、要做成品時 |
| 陸昭 | 拿四條驗收標準逐條對成品，寫自檢報告，驗不到的照實寫 | 成品做出來、要交出去之前 |

為什麼這樣分：一般遊戲公司照部門分，編劇交美術、美術交建模、建模交程式，四段接力，每接一次掉一次語境。這裡照「做出一個能玩的東西需要哪三件事」分，交接只有一次，驗收的人從第一天就讀標準。中控台第八區接上了「人才」，看得到現在誰在做什麼。

## 從別人那裡借了什麼

借的是做法，不是整包。

- 從 Donchitos 的 Claude Code Game Studios 借「先問再動手」：它每個角色都先問你、給你幾個選項、你核准才寫檔。還有它那個可以回頭的檢查點：每一項你接受的就是一個可以回去的點，要調數值就生出一個每個數值都有滑桿的面板。我打算讓人才也照這樣：劇情這種東西，先給我兩三個選項，我選了才往下做。
- 從 Orca 借「一個任務一條」：不要一個 AI 從頭包到尾，一件事交給一位人才，做完交出去，我看頭尾。
- 不想變成 Cydoc：開公司就是為了獲利，做了七年、營收不到三萬美元那種，我不想要。

我自己定的那一條：劇情設計要跟著我的大綱走，AI 不能自己改大綱。新的一關要怎麼設計，先讓它告訴我它打算怎麼做，我再決定。
